Architecture

Data Flow

The complete data path from a Linux application down to the W77Q/T secure flash chip:

Linux application (pkcs11-tool, OpenSSL, custom app) │ ▼ PKCS#11 API (libckteec.so) OP-TEE Secure World │ PKCS#11 Trusted Application ▼ File system - LittleFS backend (power-fail safe metadata updates) │ ▼ w77q_read / w77q_write / w77q_erase_sector QLIB — authenticated session library (libqlib.a) │ ▼ PLAT_SPI_WriteReadTransaction R-Car V4H RPC-IF SPI controller → W77Q/T flash chip

Layer Descriptions

LayerDescription

tee_lfs_storage.c + w77q_lfs_port.cLittleFS storage backend with authenticated flash I/O via QLIB, mount/format-on-first-boot, power-fail-safe metadata updates

QLIB (libqlib.a)Winbond prebuilt library — manages authenticated SPI sessions, key derivation, secure commands
qlib_platform.cBoard-specific SPI driver — R-Car V4H RPC-IF register-level transfers + OP-TEE crypto callbacks
W77Q/T chipHardware secure NOR flash — enforces section access policies, monotonic counters, OTP keys

Security Boundary

SPI flash is locked to Secure World. BL31 writes LIFEC register 0xE611007C bit 22 to prevent Normal World (Linux) from accessing the RPC-IF SPI controller. All flash I/O must go through OP-TEE after this point.

Storage Architecture

W77Q/T Flash (64 MB total) ┌─────────────────────────────────────────────────┐ │ Section 0 (4 MB) — Boot Firmware │ 0x000000 – 0x3FFFFF │ BL2, BL31, OP-TEE, U-Boot │ Read-only after provisioning ├─────────────────────────────────────────────────┤ │ Section 1 (16 MB) — PKCS#11 Storage │ 0x400000 – 0x13FFFFF │ LittleFS volume (tokens, keys, certs, meta) │ Authenticated R/W session │ Mounted by tee_lfs_storage in OP-TEE │ │ Geometry from W77Q_LFS_* configuration │ ├─────────────────────────────────────────────────┤ │ Remaining — Reserved / Unused │ 0x1400000 – 0x3FFFFFF └─────────────────────────────────────────────────┘

Block size tip: For deployments with 20–50 PKCS#11 objects, setting W77Q_LFS_BLOCK_SIZE = 8192U in w77q_lfs_port.h reduces flash erase operations by up to 4× compared to the default 4 KB block. Outside that range the default 4 KB block is more efficient. Note that changing block size requires a storage reformat (all objects are lost).
