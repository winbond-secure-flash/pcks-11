Configuration

Production keys must be replaced before deployment.
The release ships with sample/development keys in w77q_config.h:
  • W77Q_CFG_KD — device master key (must change)
  • W77Q_CFG_KD1 — pre-provisioning factory key (do not change, must match chip OTP)
W77Q_CFG_KD is a publicly known sample value and provides no security. Replace it with your own unique 128-bit key before production use.

Configuration File

All user-configurable settings are in a single header file:

recipes-bsp/optee/files/qlib-tee/w77q_config.h

Edit this file to change:

  • Keys: W77Q_CFG_KD (customer-editable; KD1 is factory-fixed)
  • Section sizes: W77Q_CFG_SECTION0_SIZE_MB, W77Q_CFG_SECTION1_SIZE_MB
  • Storage section index: W77Q_CFG_STORAGE_SECTION

After editing, rebuild OP-TEE to apply changes:

bitbake optee-os -c cleansstate && bitbake optee-os

Provisioning Overview

W77Q/T secure flash requires one-time provisioning to:

  1. Configure flash sections (size, offset, access policies)
  2. Write cryptographic keys to the W77Q/T OTP area
  3. Enable authenticated access to storage sections

There are two provisioning paths in this release:

PathWhereWhat it does
Boot-time provisioning w77q_qlib.c → w77q_configChip() Configures Section 1 (4 MB, read/write, plain access). Runs inside OP-TEE at boot.
Factory provisioning (PTA) w77q_provision_pta.c + w77q-provision CLI Accepts master key + section key from Normal World; writes to W77Q/T OTP via QLIB_ConfigDeviceMultiDie.

Section Layout

SectionOffsetSizeAccessUsage
00x0000004 MBRead-only (after provisioning)Boot firmware storage
10x4000004 MBRead/Write (authenticated session)PKCS#11 object storage

Factory Provisioning (Normal World Tool)

# On the board (run once on a blank W77Q/T chip):
w77q-provision \
    --master-key 00112233445566778899aabbccddeeff \
    --section-key aabbccddeeff00112233445566778899
The provisioning tool communicates with the Provisioning Pseudo-TA running in OP-TEE Secure World. Keys are passed via shared memory and written to W77Q/T OTP — they never touch the filesystem.

Boot-Time Provisioning

On first boot runs automatically to configure the flash section layout. On subsequent boots it is skipped.

Key Derivation

Section keys (Full-access Key and Restricted Key) are derived from the W77Q/T device ID (WID) using SHA-256 with a fixed label:

FK = SHA256(WID[8] || "W77Q_SECTION1_FK")[0:15]   // truncated to 128 bits
RK = SHA256(WID[8] || "W77Q_SECTION1_RK")[0:15]
KeyFull NamePurpose
FKFull-access KeyGrants read/write/erase access to the section. Used by OP-TEE to open an authenticated session for PKCS#11 object storage.
RKRestricted KeyGrants read-only access to the section. Can be used for integrity verification without write permission.

The labels "W77Q_SECTION1_FK" and "W77Q_SECTION1_RK" are hardcoded diversification strings — they ensure the two keys are different even though both are derived from the same WID. This ensures each physical chip gets unique section keys derived from its hardware identity, even when the same firmware image is deployed across a production batch.
