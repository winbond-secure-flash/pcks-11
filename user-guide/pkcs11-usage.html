PKCS#11 Usage

The PKCS#11 module path is /usr/lib/libckteec.so. Use it with any PKCS#11-compatible tool or application.

Installed Files

FileDescription
/usr/lib/optee_armtz/fd02c9da-306c-48c7-a49c-bbd827ae86ee.taPKCS#11 Trusted Application
/usr/lib/libckteec.soPKCS#11 client library (module path)
/usr/bin/pkcs11-toolOpenSC command-line PKCS#11 utility

Initialize a Token

# Initialize token on slot 0
pkcs11-tool --module /usr/lib/libckteec.so \
    --init-token --label "W77Q-Token" --so-pin 12345678

# Set user PIN
pkcs11-tool --module /usr/lib/libckteec.so \
    --init-pin --token-label "W77Q-Token" --so-pin 12345678 --new-pin 1234

Generate Key Pairs

RSA 2048

pkcs11-tool --module /usr/lib/libckteec.so \
    --token-label "W77Q-Token" --pin 1234 \
    --keypairgen --key-type rsa:2048 --label "rsa-key"

EC P-256

pkcs11-tool --module /usr/lib/libckteec.so \
    --token-label "W77Q-Token" --pin 1234 \
    --keypairgen --key-type EC:prime256v1 --label "ec-key"

AES 256

pkcs11-tool --module /usr/lib/libckteec.so \
    --token-label "W77Q-Token" --pin 1234 \
    --keygen --key-type aes:32 --label "aes-key"

Sign Data

echo "Hello W77Q/T" > /tmp/data.txt

pkcs11-tool --module /usr/lib/libckteec.so \
    --token-label "W77Q-Token" --pin 1234 \
    --sign --mechanism SHA256-RSA-PKCS \
    --label "rsa-key" \
    --input-file /tmp/data.txt \
    --output-file /tmp/sig.bin

Verify Signature

pkcs11-tool --module /usr/lib/libckteec.so \
    --token-label "W77Q-Token" --pin 1234 \
    --verify --mechanism SHA256-RSA-PKCS \
    --label "rsa-key" \
    --input-file /tmp/data.txt \
    --signature-file /tmp/sig.bin

List Objects

pkcs11-tool --module /usr/lib/libckteec.so \
    --token-label "W77Q-Token" --pin 1234 \
    --list-objects

Delete Objects

pkcs11-tool --module /usr/lib/libckteec.so \
    --token-label "W77Q-Token" --pin 1234 \
    --delete-object --type privkey --label "rsa-key"

Use with OpenSSL

OpenSSL can use the PKCS#11 module via the pkcs11 engine or provider:

Generate a Self-Signed Certificate

openssl req -new -x509 \
    -engine pkcs11 -keyform engine \
    -key "pkcs11:token=W77Q-Token;object=rsa-key;pin-value=1234" \
    -out /tmp/cert.pem -days 365 \
    -subj "/CN=W77Q/T Test/O=Winbond"

TLS Server Test

# Start a test TLS server using the PKCS#11 key
openssl s_server -engine pkcs11 \
    -keyform engine \
    -key "pkcs11:token=W77Q-Token;object=rsa-key;pin-value=1234" \
    -cert /tmp/cert.pem -accept 4433

Use with ssh-agent

# Add PKCS#11 module to ssh-agent
ssh-add -s /usr/lib/libckteec.so

# List keys (shows PKCS#11 keys alongside regular SSH keys)
ssh-add -L

Session Management Best Practice

Minimize C_Login calls — each login writes to flash.
On this PKCS#11 implementation, every C_Login updates OP-TEE's token database (token.db) on the LittleFS volume, triggering two copy-modify-write operations on the underlying flash erase blocks. Calling C_Login repeatedly (e.g. once per cryptographic request) accumulates wear and shortens flash lifetime.

Best practice: open a session, log in once, and keep that session open for the lifetime of the application process, reusing it across all C_Sign, C_Decrypt, and other operations.
